# Jira board watcher: уведомления о новых задачах на доске

Два независимых варианта уведомлений о новых задачах на доске Jira в заданном статусе:

| Вариант | Что нужно | Когда подходит |
|---|---|---|
| **Расширение Chrome** (`extension/`) | только браузер Chrome и доступ к Jira | Telegram Bot API недоступен из вашей сети (например, блокировка российских адресов) |
| **Python-бот** (`main.py`) | Python 3.10+ и доступ к Telegram Bot API | уведомления нужны в Telegram, и сеть до API есть или есть SOCKS/HTTP-прокси |

Оба варианта используют Jira Agile REST API, опрашивают доску по JQL `status = "<статус>"` и не требуют входящих соединений или публичного webhook. Логика одна: первый опрос запоминает существующие задачи, дальше уведомления приходят только по новым.

## Вариант 1: расширение Chrome (без Telegram)

Если Telegram Bot API из вашей сети недоступен (российские IP блокируются, а прокси внутри приложения Telegram наружу не отдаётся), проще не бороться с сетью, а показывать **системные уведомления Chrome**. Расширение работает в браузере, где уже открыта Jira: отдельный VPN, прокси и токены не нужны.

Установка: `chrome://extensions` → включить «Режим разработчика» → «Загрузить распакованное расширение» → выбрать папку `extension`. Дальше нажать на иконку расширения и указать адрес доски, статус и интервал. Подробности — в [`extension/README.md`](extension/README.md).

## Вариант 2: Python-бот в Telegram

Python-бот периодически проверяет задачи на доске Jira и отправляет сообщение в Telegram, когда задача появляется на доске в заданном статусе. Он использует Jira Agile REST API и Telegram Bot API.

## Важно про корпоративный VPN

И бот, и расширение должны работать там, где **уже есть сетевой доступ к Jira**: на рабочем компьютере с подключённым VPN или на сервере внутри корпоративной сети. Ни бот, ни расширение не подключают корпоративный VPN и не должны хранить логин/пароль от VPN. Если Jira недоступна, нужно настроить VPN/маршрут/DNS на хосте, где всё работает.

В Python-боте учётные данные Jira и Telegram задаются через переменные окружения (локально — файл `.env`, который исключён из Git). Расширение хранит настройки в профиле Chrome и по умолчанию использует текущую сессию Jira. Не добавляйте секреты в исходный код или коммиты. Для Jira Cloud обычно используется email + API token с `JIRA_AUTH_MODE=basic`; для Jira Data Center можно использовать username/password или PAT с `JIRA_AUTH_MODE=bearer`. Если ваша Jira разрешает доступ по сессионным cookies, можно использовать `JIRA_AUTH_MODE=cookie` и передать полный заголовок Cookie через `JIRA_COOKIE`. Cookie — секрет уровня пароля, он может истечь; не пересылайте его в чат и не коммитьте.

## Быстрый запуск Python-бота

Требуется Python 3.10+.

1. Создайте Telegram-бота через [@BotFather](https://t.me/BotFather), скопируйте токен. Напишите боту `/start`. Укажите `TELEGRAM_CHAT_ID` личного чата или группы (для группы добавьте бота и используйте ID группы).
2. Скопируйте полный адрес доски Jira из браузера — он и задаёт доску, например `https://jira.example.com/jira/software/c/projects/PROJ/boards/42` (для старой доски подойдёт `https://jira.example.com/secure/RapidBoard.jspa?rapidView=42`, для REST — `https://jira.example.com/rest/agile/1.0/board/42/issue`). Отдельные переменные для хоста и ID доски не нужны: базовый URL Jira и номер доски бот определяет из этого адреса сам.
3. Создайте локальные настройки и заполните значения:

   ```bash
   cp .env.example .env
   chmod 600 .env
   # отредактируйте .env
   ```

   Проверьте, что `JIRA_STATUS` точно совпадает с названием нужного статуса в Jira. По умолчанию это `Ревью СА выполнено`; чтобы поменять статус, достаточно изменить одну переменную.
4. Установите зависимости и запустите процесс **при подключённом VPN**:

   ```bash
   python3 -m venv .venv
   . .venv/bin/activate
   pip install -r requirements.txt
   set -a; . ./.env; set +a
   python main.py
   ```

При первом запуске `NOTIFY_EXISTING_ON_START=false` (по умолчанию) бот запоминает уже существующие задачи в статусе и не засыпает ими чат. Затем он сообщает о новых задачах, появившихся в выборке. Если нужно получить уведомления и по уже существующим задачам при первом запуске, установите `NOTIFY_EXISTING_ON_START=true`. Состояние дедупликации хранится в `data/seen_issues.sqlite3`, поэтому после рестарта повторных уведомлений по тем же задачам не будет. Для чистого старта остановите процесс и удалите эту локальную базу.

## Переменные конфигурации

| Переменная | Обязательна | По умолчанию | Назначение |
|---|---:|---|---|
| `JIRA_BOARD_URL` | да | — | Полный адрес доски Jira из браузера; из него определяются базовый URL Jira и ID доски |
| `JIRA_STATUS` | нет | `Ревью СА выполнено` | Точное имя статуса для JQL-фильтра |
| `JIRA_AUTH_MODE` | нет | `basic` | `basic`, `bearer`, `cookie` или `none` |
| `JIRA_USERNAME` / `JIRA_PASSWORD` | для `basic` | — | Логин и пароль/API token Jira |
| `JIRA_TOKEN` | для `bearer` | — | Jira Personal Access Token |
| `JIRA_COOKIE` | для `cookie` | — | Полное значение HTTP-заголовка Cookie из сессии Jira; секрет, может истечь |
| `TELEGRAM_BOT_TOKEN` | да | — | Секретный токен бота |
| `TELEGRAM_CHAT_ID` | да | — | Получатель уведомлений |
| `POLL_INTERVAL_SECONDS` | нет | `60` | Интервал опроса (минимум 5 секунд) |
| `REQUEST_TIMEOUT_SECONDS` | нет | `20` | Таймаут HTTP-запросов |
| `DATABASE_PATH` | нет | `data/seen_issues.sqlite3` | Путь к SQLite-базе состояния |
| `NOTIFY_EXISTING_ON_START` | нет | `false` | Уведомлять ли обо всех совпадениях при самом первом запуске |

### Форматы `JIRA_BOARD_URL`

| Что скопировано | Пример |
|---|---|
| Страница доски (Jira Cloud) | `https://company.atlassian.net/jira/software/c/projects/PROJ/boards/42` |
| Страница доски (Jira Data Center, старый интерфейс) | `https://jira.example.com/secure/RapidBoard.jspa?rapidView=42` |
| REST-эндпоинт доски | `https://jira.example.com/jira/rest/agile/1.0/board/42/issue` |

Если Jira развёрнута с context path (например, `https://host/jira/...`), используйте REST-форму адреса: тогда префикс `/jira` попадёт и в ссылки на задачи в Telegram. В остальных случаях ссылки строятся от корня хоста.

Бот опрашивает Jira раз в интервал и отправляет только одну нотификацию на ключ задачи. Как и любой polling, он не может обнаружить событие, которое появилось и исчезло между опросами.
