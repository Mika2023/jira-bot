# Jira board watcher — расширение для Chrome

Расширение опрашивает доску Jira и показывает **системное уведомление Chrome**, когда задача
появляется на доске в выбранном статусе. Telegram не используется, поэтому блокировки Bot API
для российских адресов не мешают, а VPN нужен только корпоративный — тот, через который открыта
Jira.

## Зачем, если есть Python-бот

Telegram Bot API недоступен из российских IP, а прокси внутри приложения Telegram (MTProto) наружу
не отдаётся — Python-боту некуда ходить. Расширение работает внутри браузера: там уже есть сессия
Jira, а уведомления рисует сам Chrome.

## Установка

1. Откройте `chrome://extensions`.
2. Включите **Режим разработчика** (переключатель справа сверху).
3. Нажмите **Загрузить распакованное расширение** и выберите папку `extension` из этого
   репозитория.
4. Нажмите на иконку расширения на панели — откроется страница настроек (она же доступна по
   кнопке «Детали → Параметры расширения»).

Обновление после правок: кнопка обновления на карточке расширения в `chrome://extensions`.

## Настройка

| Поле | Что указать |
|---|---|
| Адрес доски Jira | Полный адрес из браузера, например `https://jira.example.com/jira/software/c/projects/PROJ/boards/42` |
| Статус | Точное название статуса в Jira |
| Интервал опроса | Минуты, минимум 1 |
| Аутентификация | `Сессия браузера` (по умолчанию), `basic` или `bearer` |
| Webhook | Необязательный URL: на него уходит POST с JSON о новых задачах |

Поддерживаемые формы адреса доски — те же, что у Python-бота: страница доски
(`…/boards/42`), старый интерфейс (`…/secure/RapidBoard.jspa?rapidView=42`) и REST-адрес
(`…/rest/agile/1.0/board/42/issue`). Из адреса берётся базовый URL (для ссылок на задачи) и номер
доски.

Кнопка **Проверить подключение** делает один запрос и показывает, сколько задач сейчас в статусе.
Кнопка **Сбросить состояние** заставляет расширение заново запомнить текущие задачи.

## Как работает

- Фоновый service worker ставит `chrome.alarms` с выбранным интервалом и опрашивает
  `/rest/agile/1.0/board/<ID>/issue` с JQL `status = "<ваш статус>"`, постранично по 50 задач.
- При самом первом опросе задачи запоминаются без уведомлений; новыми считаются те, чьего ключа нет
  в состоянии.
- О новых задачах показывается 1–3 отдельных уведомления, при большем числе — одно сводное.
  Клик по уведомлению открывает задачу в Jira.
- Состояние (ключи задач) и настройки лежат в `chrome.storage.local`. Записи старше 30 дней
  удаляются автоматически.
- На иконке расширения показывается число новых задач; при ошибке — красный `!`, а текст ошибки
  виден на странице настроек.

## Ограничения

- Chrome должен быть запущен: в MV3 опрос идёт по будильникам расширения. При закрытом браузере
  уведомлений не будет, после запуска опрос продолжится.
- Режим «Сессия браузера» требует, чтобы Jira была открыта в этом же профиле Chrome и
  пользователь был залогинен; при истечении сессии появится ошибка 401.
- Если Jira доступна только по корпоративному VPN, VPN должен быть включён на этой машине.
- Логин/пароль/токен в режимах `basic`/`bearer` хранятся в профиле Chrome в открытом виде.
  На общем компьютере используйте режим сессии.

## Тесты

Логика (разбор адреса, JQL, пагинация, дедупликация) вынесена в чистые модули и покрыта тестами,
которые гоняются в Node — без браузера:

```bash
cd extension
node --test "tests/*.test.js"
```

## Структура

| Файл | Назначение |
|---|---|
| `manifest.json` | Манифест MV3: права, service worker, страница настроек |
| `background.js` | Опрос по будильнику, дедупликация, уведомления, badge, webhook |
| `board-url.js` | Разбор адреса доски в базовый URL и номер доски |
| `jira.js` | JQL, аутентификация, постраничное чтение задач, тексты уведомлений |
| `state.js` | Чистые функции состояния (что считать новым, очистка старых записей) |
| `options.html` / `options.js` / `options.css` | Страница настроек и проверка подключения |
| `tests/` | Тесты на `node:test` |
